# 迁移代次测试场景

状态：测试用例规格。代次策略持久化／清理与未变化对象不重传但删源的契约已在隔离 Single／双副本 Cluster 和 Local 上验证，范围见 [实验室说明](../lab/README.md)。本页其他完整任务、取消及故障组合仍需逐项验收，不能据规格认定通过。

## 公共准备与记录

使用独立的受控源／目标目录和明确 job ID，记录每次执行的配置、执行身份、源／目标内容与路径、已确认结果、退出状态和注入故障。校验文件实际内容及元数据，不只依赖退出码或累计数；测试结束清理自有数据。

## MIG-GEN-01：保留源端后切换为删除源端

1. 准备源文件，执行保留源端的全量迁移并确认成功。
2. 在源端分别保留未变化文件、新增文件、修改已有文件，以相同 job ID 改为删除源端迁移。
3. 验证变化内容按增量迁移处理，历史已复制但仍在源端的对象也按本次删除策略处理。分别覆盖上一保留代次为全量／增量及成功／失败／取消；已有复制代次而没有任何确认行时也不误判为新全量。
4. 删除前对应目标副本必须可靠保存当前源对象；变化对象先完成当前内容迁移，失败或结果未知时不误删。核对最终内容、源端残留、统计和任务结果。

## MIG-GEN-02：连续删除源端的迁移

1. 执行删除源端的首次全量迁移并确认成功，记录最终源／目标状态。
2. 准备下一轮当前源端对象，使用相同 job ID、保持删除源端策略启动新代次。
3. 验证按全量语义处理当前源端对象，不因历史已迁移记录跳过；目标可靠保存后再确认对应源端删除。
4. 分别令上一删除代次成功、失败、取消，含首次事实尚未入库的情况；下一删除代次均重新全量，旧 base 清空后启动，源端缺失不反向删除目标。文件级有效断点仍按传输策略核验，不恢复扫描位置。
5. 延迟并最终拒绝单项入库，验证目标就绪后源删除不等待该确认；目标数据及元数据失败仍阻断对应源删除。最终数据库错误进入 callback，保留有效目标，允许记录缺失，不要求目标对账补记。

6. 本轮收尾完成后检查该 job 的 base 为空，独立代次策略、最终报告和错误明细仍可查询；另一个 job 的 base 不受影响。复制／目录收尾期间不得提前清空。异常清理、未确认响应及旧执行延迟操作不能影响新轮次；本项收尾清理验证仍待实现与执行。

## MIG-GEN-03：增量失败后出现无法识别的 rename

1. 完成保留源端的全量迁移，再以相同 job ID 启动保留源端的增量迁移。
2. 选定文件 F 或目录 D，让它在这一增量轮次中完成比较；直接查询 ClickHouse，确认该项 `current_state` 相对上轮成功基线已经变化，再触发连接故障／异常退出。尚未比较的项、只修改内存状态或随机中断均不满足本例前置条件。
3. 确认旧执行退出之后，rename 第 2 步已比较且已改变数据库状态的同一项 F 或 D，再以相同 job ID 增量执行。目录同时核对后代路径，不能另选未被比较的条目代替。
4. 核对稳定源身份、上次确认的目标路径、本轮观察路径及实际源／目标；不能仅凭新旧 `current_state`、ctime 顺序或相同句柄恰有两行推断 rename。无法确定身份／发布归属时安全复制并核验，不能静默遗漏或误删。
5. 扩展为再次增量比较后又异常退出，再 rename 同一项的链式情形；覆盖数据库合并前／后、已比较未执行物理 rename、已执行但未确认、rename 同时修改数据／元数据，以及目录后代尚未比较等边界。
6. 最终核对当前源路径对应的目标内容和元数据、旧目标处理、基线与计数；逐阶段证据必须证明被 rename 的确是异常退出前状态已变化的项。

## MIG-GEN-04：删除源端后切换为保留源端

1. 在隔离目录完成一个源文件的数据和元数据复制，并受保护删除该源文件，保留数据库复制事实和目标文件。
2. 分别让上一删除代次成功提交或保持未完成，以相同 job ID 改为保留源端。
3. 验证选择全量且同步清空旧 base，不根据上轮已搬走项生成反向目标删除。包括上轮确认记录缺失、源端为空和当前源端有新文件等情形。
4. 核对既有目标内容、inode／ctime 不变，新增文件正常复制，当前源端保留；无反向删除项时不能仅因源端没有原文件而报丢失。
