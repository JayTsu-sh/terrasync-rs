# 迁移代次测试场景

状态：测试用例规格，尚未在本轮实现自动化或执行实测。本文不作为通用开发约束；实现行为与验收结果分别由当前代码和实际测试证据确认。

## 公共准备与记录

使用独立的受控源／目标目录和明确 job ID，记录每次执行的配置、执行身份、源／目标内容与路径、已确认结果、退出状态和注入故障。校验文件实际内容及元数据，不只依赖退出码或累计数；测试结束清理自有数据。

## MIG-GEN-01：保留源端后切换为删除源端

1. 准备源文件，执行保留源端的全量迁移并确认成功。
2. 在源端分别保留未变化文件、新增文件、修改已有文件，以相同 job ID 改为删除源端迁移。
3. 验证变化内容按增量迁移处理，历史已复制但仍在源端的对象也按本次删除策略处理。
4. 删除前对应目标副本必须可靠保存当前源对象；变化对象先完成当前内容迁移，失败或结果未知时不误删。核对最终内容、源端残留、统计和任务结果。

## MIG-GEN-02：连续删除源端的迁移

1. 执行删除源端的首次全量迁移并确认成功，记录最终源／目标状态。
2. 准备下一轮当前源端对象，使用相同 job ID、保持删除源端策略启动新代次。
3. 验证按全量语义处理当前源端对象，不因历史已迁移记录跳过；目标可靠保存后再确认对应源端删除。
4. 另设同代中断恢复子用例，区分新代次与未完成执行的继续，核对部分完成事实和最终内容。

## MIG-GEN-03：增量失败后出现无法识别的 rename

1. 完成保留源端的全量迁移，再以相同 job ID 启动保留源端的增量迁移。
2. 在部分内容已处理、任务尚未完成时注入真实连接故障，记录已确认副作用与未知结果，使任务失败。
3. 源端执行 rename，并准备不能依赖原关联证据识别 rename 的条件，然后再次迁移。
4. 核对成功基线、失败执行结果与当前源／目标事实；验证通过重新核验或安全处理完成当前迁移，最终不漏迁、不误删、不错误跳过，基线和统计与实际结果一致。

## 扩展组合

按相关实现扩展失败／取消／完成后重复启动、相同 job ID 并发或旧执行未退、路径／过滤／目标／运行配置变化等组合。每个用例写明准备状态、配置变化、操作／注入步骤、可观察预期和实际结果；执行前不标为通过。
