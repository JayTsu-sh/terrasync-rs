# 扫描性能基准：PR #135 与 PR #137

2026-11-06 按用户要求，将这两次已验收结果固定为后续性能优化和重构的历史基准。后续报告同时列出历史成绩、同环境 A/B 差值及整轮内存；当前诊断轮次单独保存。

## 配置与计量

- 源：`nfs://10.131.5.221/m1-source`；历史数据为 **50,000,007 文件、3,368,427 目录**。
- 扫描并发 **16**，数据库批次 **100,000**；ClickHouse **2 分片 × 3 副本**。
- 历史吞吐单位是**文件/秒**，目录不计入文件数。后续同时报告普通文件/秒与包含目录的条目/秒，并明确分母。
- 整轮耗时包含应用主动整理、写库、比较、删除识别、最终统计及提交；续扫另外记录确认点、恢复净产出、回退和中断前后总耗时。
- RSS 使用扫描进程整轮峰值，包含最终化；另报曲线、前后段变化。约 200 MiB 继续作为内存优化目标。

## PR #137：变化比例与整轮内存基准

来源：[PR #137](https://github.com/JayTsu-sh/terrasync-rs/pull/137) 和 [f7e6f98 中保存的架构记录](https://github.com/JayTsu-sh/terrasync-rs/blob/f7e6f988b1ef13d2e649a2ecb06a28ab4bf25798/.claude/docs/architecture.md)。
主体实现采用同一正式 release 二进制复验；无 DB 基线 **966.88 秒**，首尾无 DB 速度差约 **0.0021%**。

| 场景 | 相对无 DB 耗时增加 | 整轮峰值 RSS |
| --- | ---: | ---: |
| 全量落库 | 0.73% | 159.79 MiB |
| 全量续扫 | 0.99% | 173.81 MiB |
| 无变更增量 | 2.63% | 521.20 MiB |
| 无变更增量续扫 | 3.29% | 554.42 MiB |
| 约 1% 增删改增量 | 2.99% | 621.57 MiB |
| 约 1% 增删改增量续扫 | 4.36% | 752.86 MiB |

三种续扫的恢复净吞吐当时也通过，三次 CLI 取消分别为 0.127／0.159／0.214 秒。最高短峰位于最终化阶段；当时增量约 200 MiB 目标尚未达到。
PR 审查追加的复制目录元数据屏障及错误源链修复有独立回归，没有再跑一次 5,000 万文件性能矩阵。

## 后续使用

性能验证沿用 **16／100,000**，并保存二进制 SHA、提交、实际源数量、部署模式、时间、完成状态与 RSS 测量方式。
全量／全量续扫接近无 DB、增量保持历史低损失，是后续优化应保有的性能水平；当前开发规范中的 5%／10% 验收目标仍需分别验证。
数据量或主机变化时，报告同环境同源对照及与历史成绩的差异；直接比较绝对耗时时需匹配数据量。
当前普通扫描使用 unordered，显式续扫使用 blocks，分别匹配自身无 DB 基线；生产 checkpoint 至少 60 秒，当前恢复与一致性要求照常验收。
历史成绩作为性能参照，当前路径的通过结论来自实际复测。
