# ClickHouse 目录与原生观察重构

## 目标与约束

按 `docs/architecture-review.md` 检查职责归属、规则集中和逻辑内聚性。当前只有 ClickHouse；Single、Cluster 是部署布局，不能用已删除的 DuckDB 为数据库注册、字符串后端选择或存储条目转换保留扩展点。

运行时条目直接使用 data-mover `ObservedEntry`。彻底删除 `EntryEnum` 及其后端条目结构；不引入重命名副本或兼容别名。跨任务共享不可变观察用 `Arc`，逐版本消息仅保存共享观察及索引。只有写 SQL、网络编码等确实需要拥有字节的边界才编码；有界批次在重试前编码一次，重用字节及去重 token。

保持当前正确性要求：原生历史顺序、null 版本、删除标记和目录对象；已确认事实、累计统计和 checkpoint 一致；取消后收束全部后台操作；不盲重试结果未知的写入。生产 checkpoint 至少间隔 60 秒，并等待完整目录块。

## 职责分配

| 所属模块 | 应承担的内容 | 应移除或迁出的内容 |
| --- | --- | --- |
| db/catalogue | 目录生命周期、查询、完成版本持久化、复制代次 | 多后端工厂、公开临时表协议、无用快照原型 |
| db/scan | 扫描代次、比较、统计、checkpoint、续扫一致性 | app 拼接的数据库状态转换 |
| db/execution | 类型化错误、请求取消、统一恢复预算、写入安全性 | app 通用指数重试 |
| db/schema | 表布局、行编码、SQL 命名与必要的查询投影 | 存储模型转换、后端事实解码 |
| app | 产品任务策略、版本选择、复制与完成事件、连接配置 | 通用存储机制和具体协议实现 |
| transport | NDX、原生快照的 wire 编码、分块流与 ACK | 产品目录状态与 ClickHouse 布局 |
| 小型任务契约 crate | app/db/transport 共用的原生观察视图和任务事件 | 存储连接、数据库、网络 I/O、后台任务 |
| data-mover | 原生存储事实、通用复制、权限、安全元数据应用 | ClickHouse、产品 job 和终态通知策略 |

`storage-adapter` 的删除必须伴随上述职责迁移；不能将整个 crate 原样搬到 app 或 utils。删除 `EntryEnum` 只消除了其中一种职责，并没有自动消除当前剩余的扫描、流式传输、配置和恢复逻辑。

## 实施顺序

1. 移除数据库注册机制，机械调整目录／执行／扫描文件布局。
2. 原生观察贯穿扫描、SQL、复制、NDX 和完成事件；删除旧条目。历史内容由逐版本视图选择；每版本目标提交后才发送成功事件。HDFS／NFS 的独立真实权限由 data-mover 捕获并进入快照，CIFS 展示权限不能用于 chmod。
3. 收敛 ClickHouse 构造与配置，删除工厂／后端类型。将目录查询、写入、表生命周期和代次状态拆到对应模块，隐藏行 DTO、SQL 和临时表细节。
4. 将批次重试收回 db，保留有类型的结果未知错误；通过明确的目录会话封装 app 当前分散的数据库协议。
5. 将纯任务契约、wire、产品编排和通用存储机制分别归位，删除 `storage-adapter` 和重复的存储后端枚举。
6. 对最终候选重新 review、运行 CI 与真实环境功能／故障／性能验证，报告证据后再处理合入。

结构迁移与行为修复分开提交；每个提交必须可编译并通过对应检查。步骤列表是验收目标，不代表已完成。

## 验证范围

- 本地：workspace check、Clippy、单元和集成测试、实际双进程 QUIC 测试、前端 CI 检查。
- 真实 Single 与 Cluster：完整／增量扫描，完成事实回读，checkpoint／续扫、代次发布、删除／重命名和未确认写入。集群覆盖 2 分片 × 3 副本。
- 真实版本化 S3：多个对象版本、null、历史与最终删除标记、目录标记及 tags；atomic 与 checkpoint，两次执行不得虚增目标版本或完成统计。非版本化目标只保留有效 latest。
- 真实 HDFS／NFS：缺少 numeric ownership 时保留真实 mode、已知的单侧主体事实；本地与 QUIC 路径分别验证，检查不安全 set-id 位剥离。
- 故障：只对本次任务使用受控网络故障，不停止共享服务；验证连接拒绝、响应停滞、连接丢失、未知写结果和取消收尾。按实际依赖执行约 3 秒恢复预算。
- 性能：候选与同一数据集、相同遍历模式的无 DB 基线比较；全量与约 1% 增删改；报告净吞吐、总耗时、峰值 RSS 和持续增长。功能测试缩短 checkpoint 间隔不能代替生产配置的性能证据。

真实环境信息来自实验室文档及 `/root/jay/cicd/lisa.md`；凭证仅由本地安全配置提供，不写入本文件、提交或测试报告。每次测试使用独立 run id，清理其临时库、对象、配置和进程。
