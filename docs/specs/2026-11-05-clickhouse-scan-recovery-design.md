# ClickHouse 扫描异常处理设计

**日期：** 2026-11-05

**状态：** 已实现并完成专项验证；完整性能验收仍在推进

## 问题

批处理不能及时暴露空闲期的数据库故障。仅对健康检查设置超时，也不能结束仍在等待响应的业务请求。原 HTTP client 未应用配置中的连接和读取超时，扫描及取消可能无限等待。

## 方案

每次扫描由数据库模块维护一个共享执行域，所有 writer 共用一次故障的恢复预算。应用扫描层负责启动、停止并等待该执行域，data-mover 继续只负责源端扫描恢复。复制等操作不自动套用扫描的重试窗口。

成功业务回执更新健康状态；最近一秒没有回执时才发只读探测，探测超时一秒。单机使用 SELECT 1；集群检查当前快照发布要求的全部配置节点，不能用前端可达代替集群可用，也不承诺现有全节点 DDL 支持降级运行。

第一次可恢复的连接错误开始三秒窗口。窗口内暂停新请求，失败请求按自身语义恢复。并发 writer、探测和嵌套步骤不各自增加三秒。探测成功只能确认探测恢复，不能清除尚未恢复的业务操作。认证、权限、SQL 和配置错误立即失败。

## 请求与一致性

- 完整只读查询可重试，保留原一致性设置。
- 批量事实、事件及 manifest 写入固定批次内容、顺序和去重 token，在目标表启用有限去重窗口后重试。去重不是永久的 exactly-once 保证。
- 普通写入关闭按内容自动去重；仅固定 token 的幂等入口显式启用，避免扫描的表设置把复制／同步中不同轮次的相同内容误判为重发。
- 快照封存由冻结的 working 事实生成；失败重试使用新的隔离快照名称，未确认对象不得进入 manifest。
- 旧执行排空的读取在构造快照前独立恢复；读取确认恢复后，正常构造新快照不继续占用该读取的故障窗口。
- 正常快照封存按当前执行身份复用首次成功的前次执行排空证明；失败不缓存，无执行域或执行身份变化时重新检查。恢复入口及 DROP／ATTACH 后的即时排空仍每次执行，不复用该证明。
- 仅对不复用的旧 batch 分区、无 manifest 引用且名称不复用的快照对象，允许幂等重发 DROP；不将此规则扩展到 working 表清空、恢复或任意 DDL。
- 其它变更不能统一重发。明确尚未建立连接的请求可重新连接；无法确定是否执行的请求保留类型化的不确定结果。
- 只有实际 ACK 后推进 checkpoint。重新执行先排空已知旧执行并检查 generation 提交结果，再决定恢复已确认快照；不能因回执丢失撤回已经提交的 generation。

底层传输使用配置中的连接及读写空闲超时。恢复耗尽或用户取消后，禁止新请求，尝试本执行标记的 KILL，并在统一的 250 毫秒收尾期限后结束本地 HTTP 等待；所有本地请求 owner 都须退出。HTTP 关闭及空匹配 KILL 不能证明服务端已经完成，故返回不确定结果，不能冒充已取消或已成功。

三秒从识别到故障开始计算，静默丢包识别耗时单独记录；本地请求及最终通知的短暂收尾耗时也单列报告。源端错误与数据库收尾错误同时出现时，保留两者类型和源路径信息。

## 最终 callback

**本次尚未实现以下结果交付策略。**

最终结果交付与扫描事实提交分开。最终 callback 首次发送失败后最多重试三次，仍失败时将准确的最终 payload 保存到可用的 ClickHouse，供 callback server 查询。保存失败不能阻止向可用 callback 报告任务错误。此项作为独立的结果交付改动验证，不能借扫描恢复成功宣称已完成。

ClickHouse 与 callback 同时不可用由上层处理；本项目不增加本地磁盘、SQLite 或其它兜底暂存。

## 性能与验证

验证覆盖单机和真实集群的无批次期间失联、请求头及响应体停滞、上传停滞、短暂断连、持续断连、取消、永久错误和实际写入后丢失回执。四种扫描模式核对事实、事件、统计、checkpoint 及新执行恢复。检查后台任务收尾，并在至少 60 秒 checkpoint 的同遍历顺序基准上复查吞吐和 RSS。

已完成以下专项检查：

- 传输及恢复单元测试、workspace 测试、格式及 Clippy 检查；单机／集群 CLI 续扫、普通元数据读写、去重作用域及快照恢复检查。
- 8 项真实 TCP 闪断、集群 Blocks checkpoint 边界闪断，以及新快照 ATTACH 且已有数据后才放行旧 DROP 的隔离检查；最终路径、事件及另一任务的路径均正确。
- 前一候选的 72 项协议故障验证全部通过；当前候选再次通过 20 项 Blocks 闪断、持续故障及提交回执丢失验证。此前测得持续故障识别后 3.02～3.10 秒退出、故障期间取消 0.04～0.09 秒；静默丢包含识别时间为 5.64～6.04 秒，不能写成实际断网起三秒。
- 当前候选首次并行验证的两项集群 CLI 用例发生前次执行检查超时；结束同时运行的 TCP 故障负载后，原并发数和原阈值重跑四项全部通过。保留失败记录，多任务压力不因此宣称已验收。
