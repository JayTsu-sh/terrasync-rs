# 外部存储与服务连通性

设计、开发、测试和 review 按实际操作考虑源端存储、目标端存储、ClickHouse 与 callback 的连通性。本规范关注连接建立失败、运行中断连、静默丢包和请求超时。

- **检测与上报**：评估连接建立、运行、提交和收尾阶段，明确检测时限和负责层。保留有类型的原因、依赖、操作阶段及未知写结果；认证／权限等明确非网络错误须准确分类，不能当作断网重试。日志与 callback 中的凭据脱敏。
- **有界恢复**：client／backend 提供协议安全的恢复与错误证据，data-mover 执行调用方指定的调度预算，本仓库负责任务、数据库和通知。逐操作明确超时、退避、重试负责人及恢复／退出条件，避免多层等待叠加；扫描、拷贝和通知分别判断。
- **扫描窗口**：源端或 ClickHouse 网络故障被识别后，同一次故障最多再恢复约 3 秒；恢复则继续，耗尽后停止并准确报告。重试、分页和并发请求不能重置该窗口；静默丢包的检测耗时另行约束和报告。
- **批处理与空闲**：批量写入、空闲和背压期间也须有界感知故障。评估请求超时是否足够；独立检查须限制频率、超时与并发，并收束其生命周期，验证正常性能、内存和连接开销。
- **一致性与取消**：响应丢失不能被当作未执行；依据幂等身份及执行证据恢复。故障与背压期间仍须秒级响应取消，处理在途操作和未知写结果，防止旧执行继续影响新执行。checkpoint、持久化事实、统计和任务状态保持一致；扫描不新增本地磁盘暂存。
- **最终通知**：最终 callback 首次失败后最多再重试 3 次；仍失败时，将准确最终载荷、任务／执行身份和发送失败信息保存到可用 ClickHouse，供上层查询。通知失败不能改变任务实际结果或被标为已交付。ClickHouse 与 callback 同时不可用由上层处理，不增加专门兜底存储或组合恢复流程。

## 真实故障注入

新增或修改外部存储／服务访问、连接、超时、重试、取消及恢复逻辑，必须对受影响真实链路实施受控故障注入，按场景覆盖闪断、持续断连、静默丢包／超时及恢复，不能仅以正常路径、单元测试或 mock 通过代替。

验证故障识别、恢复或退出、故障期间取消、最终数据与任务状态、资源收尾及正常运行开销。按影响范围覆盖全量／增量／续扫和 ClickHouse 单机／集群；报告注入对象与方式、实际结果、检测耗时、识别后恢复／退出耗时、取消耗时及未覆盖项。遵守实验室允许范围和清理要求。

本页是设计与验收要求，当前实现与达标结论以实际代码和验证证据为准。
