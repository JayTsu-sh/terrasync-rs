# 外部存储与服务连通性

设计、开发、测试和 review 按实际操作考虑源端存储、目标端存储、ClickHouse 与 callback 的连通性。本规范关注连接建立失败、运行中断连、静默丢包和请求超时。

- **检测与上报**：评估连接建立、运行、提交和收尾阶段，明确检测时限和负责层。保留有类型的原因、依赖、操作阶段及未知写结果；认证／权限等明确非网络错误须准确分类，不能当作断网重试。日志与 callback 中的凭据脱敏。
- **有界恢复**：client／backend 提供协议安全的恢复与错误证据，data-mover 执行调用方指定的调度预算，本仓库负责任务、数据库和通知。逐操作明确超时、退避、重试负责人及恢复／退出条件，避免多层等待叠加；扫描、拷贝和通知分别判断。
- **扫描窗口**：源端或 ClickHouse 网络故障被识别后，同一次故障最多再恢复约 3 秒；恢复则继续，耗尽后停止并准确报告。重试、分页和并发请求不能重置该窗口；静默丢包的检测耗时另行约束和报告。
- **批处理与空闲**：批量写入、空闲和背压期间也须有界感知故障。评估请求超时是否足够；独立检查须限制频率、超时与并发，并收束其生命周期，验证正常性能、内存和连接开销。
- **一致性与取消**：响应丢失不能被当作未执行；依据幂等身份及执行证据恢复。故障与背压期间仍须秒级响应取消，处理在途操作和未知写结果，防止旧执行继续影响新执行。checkpoint、持久化事实、统计和任务状态保持一致；扫描不新增本地磁盘暂存。
- **迁移与异步记账**：目标数据、所需元数据、所选校验和所需持久性成功，复核源及执行身份后可以删除源端，不等待逐项 ClickHouse 入库。事实有界异步批量写入，最终未恢复错误明确上报，允许记录缺失；已完成搬迁不回滚。保留源端的增量可能重复制缺失项，上一代删除源端时，本代无论保留还是删除源端均重新全量，防止反向删除已搬迁目标，不新增专门对账或回执链路。持续数据库故障仍按预算停止新调度并收束，不把允许缺失理解为无限脱库运行。
- **最终通知**：准确最终报告及任务／执行身份保存到可用 ClickHouse，供外部应用查询，不以是否配置 callback 或发送成功作为保存条件。最终 callback 首次失败后最多再重试 3 次；重试载荷和身份保持不变。callback 发送失败的原因只记日志，不写入 ClickHouse。HTTP 2xx 即外部 callback 已接收，不要求响应体返回 batch_id，不跟随重定向；每批接收成功后清理该批待发错误明细，累计 entry／任务错误数不减少。ClickHouse 内部确认只用于发送方避免重发，不表示外部业务处理完成，报告原文继续保留。通知失败不能改变任务实际结果或被标为已接收。ClickHouse 与 callback 同时不可用由上层处理，不增加专门兜底存储或组合恢复流程。

## 错误明细通知

最终未恢复错误通过有界队列及 ClickHouse 分页保存／发送，重放不再次累计统计。运行时按最多 64 条归档前缀背压，不以省略数字代替完整明细；未恢复 checkpoint 且无错误时不新增诊断表读写。归档响应不明时保留同一批身份，重试不能撤销已确认记录。HTTP 2xx 后内部确认暂时失败时，只重试确认，不主动重发本进程已经接收成功的批次；在接收成功、确认及 checkpoint 之间进程崩溃仍可能重复投递，接收方应按事件身份幂等。

`diagnostics_complete` 仅在终态错误明细全部排空、内部确认完成且未发生遗漏时为 true。分批终态之后还会发送无明细的最终汇总，接收端允许同次执行的更大序号终态报告更新快照，普通周期进度不能覆盖终态。通知恢复的预算独立于扫描预算；当前诊断数据库恢复窗口不能视为整个迁移已具备统一故障控制。

## 真实故障注入

新增或修改外部存储／服务访问、连接、超时、重试、取消及恢复逻辑，必须对受影响真实链路实施受控故障注入，按场景覆盖闪断、持续断连、静默丢包／超时及恢复，不能仅以正常路径、单元测试或 mock 通过代替。

验证故障识别、恢复或退出、故障期间取消、最终数据与任务状态、资源收尾及正常运行开销。按影响范围覆盖全量／增量／续扫和 ClickHouse 单机／集群；报告注入对象与方式、实际结果、检测耗时、识别后恢复／退出耗时、取消耗时及未覆盖项。遵守实验室允许范围和清理要求。

本页是设计与验收要求，当前实现与达标结论以实际代码和验证证据为准。
